# 実 IUT 完全証明率の客観メトリクス（分母固定・分子は独立監査）

## 何のためか
`complete_pct`（実 IUT 完全証明率）を**実装者の自己申告から切り離し**、機械計算量にする。第140–147弾で「模型作業で +1%」の水増しが起きたため、その再発を仕組みで防ぐ。

## 仕組み（人手承認なし）
1. **分母＝固定台帳**（`target_ledger.json`）：実 Cor 3.12 に必要な実対象の部品リストと weight。**先に固定**し、後から水増ししない。
2. **分子＝独立監査**（`AUDIT_RUBRIC.md`）：独立エージェントが**実 Lean 定義のみ**から各部品の `status`（0=実対象なし/模型のみ, 0.5=実の忠実部分ケース, 1=実で完成）を評定して台帳に埋める。**実装者は status を付けない。**
3. **計算**：`tools/compute_complete_pct.py` が `complete_pct(柱)=Σ(weight*status)/Σ(weight)*100` を機械計算。
4. **フック**（`.claude/hooks/complete_pct_guard.sh`, Stop/SubagentStop）：
   - 監査済みの柱は `graph-meta.json` の値が台帳計算値と一致必須（ズレをブロック）。
   - 未監査（status に null が残る）柱は、監査で埋まるまで凍結値（`.complete_pct_frozen.json`）を超えられない。
   - **実装者が手で complete_pct を盛るのは不可。数字は台帳計算からのみ。**

## 客観性の芯と限界（正直に）
- 芯：独立文脈＋敵対的スタンス＋実定義への強制的接地＋**再現可能**（ユーザーがいつでも監査を再実行して照合できる）。
- 限界：監査エージェントも LLM でグラウンドトゥルースではない。フックは「自己申告の遮断」と「台帳整合の強制」であって、realness の完全なオラクルではない。最終的な芯の担保はユーザーの再監査。
- ユーザーは**承認フロー（判子）に立たない**。数字を動かす正規経路は「独立監査→台帳 status→自動計算」。
